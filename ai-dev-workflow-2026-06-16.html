Operating model
Relay → Single-driver front

BAs drive the front end-to-end. The designer shepherds the build, so the BA never becomes a help desk — and only business-logic questions come back upstream.

The pipeline

Five stages, gated handoffs

Each stage hands one artifact forward. Gates keep speed honest — nothing moves until the prior gate clears.

The spec contract

Two sources of truth

A prototype shows the happy path and the look. It can't show the invisible logic. So the contract is split — and the BRD stays light because it stops re-describing the UI.

Prototype

Authoritative for UI + flow
  • What it looks like
  • Screen order & navigation
  • Components from the design system

BRD

Authoritative for logic
  • Business rules & permissions
  • Empty / error / loading states
  • Edge cases & failure handling
  • Acceptance criteria (given / when / then)

QA tests against both.

規格契約

兩個真實來源

原型呈現主要流程與外觀，卻無法呈現隱藏的邏輯。因此契約一分為二 — BRD 也因為不再用文字重述 UI 而保持精簡。

原型

UI ＋ 流程的權威依據
  • 外觀樣式
  • 畫面順序與導覽
  • 來自 design system 的元件

BRD

邏輯的權威依據
  • 商業規則與權限
  • 空白／錯誤／載入狀態
  • 邊界情況與失敗處理
  • 驗收條件（given／when／then）

QA 對照兩者測試。
