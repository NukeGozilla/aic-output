How the batch tool works (BR-12 → BR-14): pick a gross-revenue band (< 3,0003,000–9,999.99≥ 10,000, all HKD) measured over a period (prior monthmonth-to-datelast 30 dayscustom range) → tick the rows (or "select all in band") → choose a commission % from 10%12%15% → Apply to selected.

Free pick — no auto-mapping: the band is purely a filter; the % Ops applies is their own choice (the system does not suggest a rate from the band). One Confirm applies the same % to every selected TM and writes one audit row per TM with source BATCH (BR-14, BR-07).

Notes for dev: changing the Period recomputes each TM's gross revenue (and therefore which band they fall in); band thresholds are inclusive-low / exclusive-high. Custom date opens a from/to range. Selection persists while paging within the active filter. Export CSV respects the active band + period.

What changed in this version

Auto mode removed from the UI. The earlier Mode (Manual / Auto) selector and the read-only "Auto · updated monthly" state are deferred (the monthly auto-tiering engine is parked for a later phase). Every TM now carries a single, admin-managed commission_rate; there is no commission_mode flag in P0.

Two ways to set a rate: Single here in Edit User (this view). Bulk via the revenue-band filter + batch tool on the Tastemaker List (View 1).

Out of scope: the front-end profile display of the % — that lives on the user profile page, the visual is owned by the designer; backend just exposes it via API (BR-11).

A TM record carries: commission_rate · updated_at · updated_by. (The auto-engine fields — commission_mode, tier table, monthly cron — return only if/when Auto is un-deferred.)
