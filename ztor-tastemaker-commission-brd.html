BR — Ztor Tastemaker Commission Rate (分成比例設定)

Last updated 2026-06-10 · Owner: Jeff · Asana: Ztor Roadmap 2026 / task 1214344674908625 (assignee Dolly)
DRAFT — NEEDS REVIEW
Goal in one line: Let Ztor Tastemakers (TMs) earn commission at different percentages — either set manually by marketing (manual mode) or auto-calculated monthly from gross revenue (auto mode), governed by a single commission_mode flag per TM.
Related decisions: 2026-05-19-tastemaker-tiered-split-deferred, 2026-06-01-backer-revenue-split-30-70.
🖼️ Companion wireframes: Edit User selector + Commission Audit Log →

1 · Problem Statement

Ztor wants to reward Tastemakers (content curators/promoters) with a share of the revenue they drive, but today there is no way to assign or vary a TM's commission rate — every TM is effectively flat/zero. Without per-TM rates, marketing cannot strike differentiated deals with high-value curators, and the platform cannot incentivise organic TMs to grow their revenue. This blocks the creator-economy monetization layer central to Ztor 2.0's "follow the money" revenue-sharing vision and leaves payout calculation as an untracked manual exercise.

3 · User Stories

US-01: As a Marketing/BO Admin, I want to assign a commission % (10/12/15) to a manual-mode Tastemaker from the Edit User screen, so that agreed deal terms are recorded in the system and flow into payouts.
US-02: As a Marketing/BO Admin, I want to see whether a TM's rate is admin-set or system-calculated, so that I don't accidentally overwrite an auto-managed rate.
US-03: As a Tastemaker (manual mode), I want to see my commission % on my profile, so that I trust the platform is paying the rate we agreed.
US-04: As a Tastemaker on auto mode (typically self-onboarded), I want my commission % to rise automatically as my monthly gross revenue grows, so that I'm rewarded for performance without negotiating.
US-05: As the Commission Engine, I want to recompute every auto-mode TM's % at month close from their prior-month gross revenue, so that rates stay current with performance.
US-06: As Finance/Ops, I want to read each TM's effective % for a given period, so that I can compute and reconcile payouts accurately.

4 · User Flow

Flow A — Manual-mode TM, admin-set rate (P0)
Step 1: Admin → opens Back Office → User list → clicks Edit on a TM row → EDIT USER modal opens
Step 2: 🔀 Decision: Is Role = "Tastemaker"?
  → YES: Commission field is shown
  → NO:  Commission field is hidden
Step 3: 🔀 Decision: Is commission_mode = "manual"?
  → YES: Commission dropdown is editable (10% / 12% / 15%)
  → NO (auto): Commission field is read-only, shows "Auto · updated monthly" + current value
Step 4: Admin → selects a % from the dropdown → clicks Confirm
Step 5: System → validates value ∈ {10,12,15} → saves rate (commission_mode stays "manual") + timestamps → closes modal
Step 6: System → records an audit entry (who, old %, new %, when)
        Exception: invalid/blank % → System blocks save, shows inline error, modal stays open
Flow B — Auto-mode TM, system rate (P1)
Step 1: Commission Engine (Cron) → fires at month close (e.g. 1st of month, 00:30)
Step 2: System → for each commission_mode = "auto" TM, reads prior-month gross revenue
Step 3: System → maps revenue to a tier → derives commission %
Step 4: 🔀 Decision: Did the % change vs current?
  → YES: System updates rate + timestamps + writes audit entry (source = "auto")
  → NO:  System leaves rate unchanged (still timestamps the run)
Step 5: System → new % is the effective rate for the new month onward
        Exception: revenue data missing for a TM → keep last known %, flag for Ops review

5 · Business Requirements

BR-01 · Commission field on Edit User (role-gated)
Description
The system SHALL display a "Commission %" field in the EDIT USER modal only when the selected Role is "Tastemaker".
Priority
🔴 Must-Have
User group(s)
Marketing/BO Admin
Measurability
Field present for Role=Tastemaker, absent for all other roles across all test accounts.
BR-02 · Manual rate selection from fixed list (manual mode)
Description
For a manual-mode Tastemaker, the system SHALL allow the admin to set the commission % from a fixed list of 10%, 12%, and 15% only.
Priority
🔴 Must-Have
User group(s)
Marketing/BO Admin
Measurability
Dropdown offers exactly {10,12,15}; no other value can be saved via UI or API.
BR-03 · Persist rate with mode & timestamp
Description
The system SHALL store the commission % per TM together with its commission_mode (manual | auto) and last-updated timestamp.
Priority
🔴 Must-Have
User group(s)
Marketing/BO Admin, Commission Engine, Finance/Ops
Measurability
Saved record returns rate, commission_mode, and ISO timestamp via API for every TM.
BR-04 · Default mode & rate for newly created Tastemakers
Description
The system SHALL default any new TM to commission_mode = manual with a commission % of ⚠️ 0%, so payouts never use a null rate and an admin must consciously set the rate.
Priority
🔴 Must-Have
User group(s)
Finance/Ops
Measurability
Every TM record returns a non-null numeric rate at all times.
BR-05 · Read-only display for auto-mode TMs
Description
For a TM with commission_mode = auto, the system SHALL render the commission field as read-only with an "Auto · updated monthly" indicator and the current value.
Priority
🔴 Must-Have
User group(s)
Marketing/BO Admin
Measurability
Auto-mode TM rate cannot be edited via the modal; indicator is shown.
BR-06 · Commission mode flag (manual | auto)
Description
The system SHALL introduce a commission_mode attribute per TM with value manual or auto, which selects which commission logic applies (admin-set vs system-calculated). No "invited/non-invited" concept exists in the system today — this flag is the mechanism, not a business tag.
Priority
🔴 Must-Have
User group(s)
Marketing/BO Admin
Measurability
Each TM has commission_mode ∈ {manual, auto}; changing it flips the field editable↔read-only and routes the monthly job accordingly.
BR-07 · Audit trail of rate changes
Description
The system SHALL log every commission-rate change with actor (admin id or "system"), previous %, new %, and timestamp. The log is immutable (append-only) and reusable both as a global view and scoped to a single TM.
Priority
🟡 Should-Have
User group(s)
Marketing/BO Admin, Finance/Ops
Measurability
Each change produces one immutable audit row retrievable by TM id.
BR-08 · Effective-rate lookup for payouts
Description
The system SHALL expose each TM's effective commission % for a given period to the reporting/payout layer.
Priority
🔴 Must-Have
User group(s)
Finance/Ops
Measurability
Reporting query returns correct %-for-period for both manual and auto TMs.
BR-09 · Monthly auto-calculation tiers (auto mode)
Description
The Commission Engine SHALL recompute each commission_mode = auto TM's % monthly by mapping prior-month gross revenue to a configured tier table. ⚠️ Tier thresholds TBD by marketing — placeholder below.
Priority
🟡 Should-Have (Phase 2)
User group(s)
Commission Engine, Auto-mode TM
Measurability
Given a revenue input, engine outputs the tier-correct % for 100% of seeded test cases.
BR-10 · Auto-run resilience & idempotency
Description
The monthly job SHALL be idempotent (safe to re-run) and SHALL, on missing revenue data, retain the TM's last known % and flag it for Ops.
Priority
🟢 Nice-to-Have (Phase 2)
User group(s)
Commission Engine, Finance/Ops
Measurability
Re-running the job for the same month produces no duplicate changes; missing-data TMs appear in a flag report.
BR-11 · Profile display hook (frontend)
Description
The system SHALL expose the TM's commission % via API for display on the user profile page (visual design owned by designer).
Priority
🟡 Should-Have
User group(s)
Tastemaker (manual & auto)
Measurability
Profile API returns current % and commission_mode for the signed-in TM.

9 · Phase Breakdown

PH-01 · Manual Commission (MVP) — admin can assign a rate to manual-mode TMs and payouts can read it
BR-01 → BR-06 → BR-02 → BR-03 → BR-04 → BR-08 → BR-07
Rationale: After this phase, marketing can set 10/12/15% on any manual-mode TM in Edit User and Finance can pull the rate for payouts — a fully usable, testable slice with no dependency on the revenue engine. (BR-06 ships the commission_mode flag defaulting to manual, so the whole MVP runs in manual mode.)
PH-02 · Auto Commission (engine) — auto-mode TMs get monthly performance-based rates
BR-05 → BR-09 → BR-10
Rationale: Adds the monthly cron + tier mapping on top of the same storage/display model. Gated on the per-TM monthly revenue feed and marketing-confirmed tier thresholds.
PH-03 · Profile surface
BR-11
Rationale: Expose the value to the frontend for the designer to place on the profile page. 💡 Optional to sequence anytime after PH-01 — can defer.
