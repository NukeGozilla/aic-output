How to take the working demo to a production Ztor feature. Green = already proven in the demo; amber = what the dev team builds to productionize. The realtime core (Ably + host-authoritative sync) carries over unchanged.

Core principle — host-authoritative sync. Only the host's player emits playback events (play / pause / seek). Every viewer is a passenger that replays them. There is no central media server doing the syncing — Ably is a thin pub/sub bus, and the video bytes come straight from the CDN to each client. This keeps the build small: the "magic" is ~3 channels and a snapshot-on-join handshake, not a streaming backend.

Sync protocol — host-authoritative
The only non-obvious part of the build. Two flows: live control (left→right propagation of host actions) and late-join catch-up (snapshot handshake). Everything rides the video-{room} channel.

Demo → Production: what the dev team changes
The demo proves the mechanism end-to-end. These are the deltas to make it a real Ztor feature — most are "reuse an existing Ztor service," not net-new infrastructure.
ConcernDemo (shipped)Production for Ztor
Identity Typed display name; random Ably clientId; ui-avatars fallback Use Ztor session. clientId = Ztor userId; name + avatar from profile. Guest share-links keep a name gate.
Video source 3 self-hosted MP4s in /public; viewer adopts URL from snapshot Ztor Video CDN (HLS + DRM). Snapshot carries videoId; client resolves a signed manifest via the entitlement resolver. Keep play/pause/seeked hooks.
Auth / capability One root key; token grants any room; host role is a client flag Per-room capability tokens. Publish on video-{room} restricted to the host (asserted from the room record), subscribe-only for viewers.
Rooms / codes Math.random() code, client-only, videoId in URL Server-created Room records; code validated on join; videoId resolved server-side (not trusted from URL).
Comments Ephemeral + 5-min Ably rewind; optimistic echo Keep live path as-is. Optionally persist + moderate by reusing crowdfund Comments/Moderation (BR-19).
Sync robustness Snapshot-on-join + manual "Force sync"; no drift correction Fine for most rooms. Optional: periodic host heartbeat to correct drift; re-snapshot on host reconnect.
Voice Not included (Ably carries no audio) Optional fast-follow: LiveKit/Daily room keyed by the same roomCode. Runs alongside, independent of sync.
