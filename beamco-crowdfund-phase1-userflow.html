Beamco Crowdfund — Phase 1 User Flow

Phase 1 Artist × Fan × Admin

End-to-end journey for both roles, the cross-role interactions, and the Phase 1 / Phase 2 boundary.

Source · Crowdfund Project BRD (Notion · 2025-12-04, reviewed 2026-03-22) · UAT · artists.beamco.co + fans.beamco.co ·

Phase 1 lets fans commit to projects.
The actual money changes hands in Phase 2.

Artists build a campaign, fans pledge to plans they like, the system tracks who's in. No one's card gets charged in Phase 1 — that's Phase 2's job. Here's how the two sides play out.

The two CTAs your team will see

These are the actual button labels in the design. Knowing which one a fan should be seeing is the fastest way to debug eligibility issues.

View Requirement

What a fan sees if they're not yet eligible. Replaces the invest button. The screen reads:
"Exclusive Access: Top Fans Only. This is reserved for {Creator}'s top fans. To qualify, either: (1) Grab something from {Creator}'s shop; or (2) Join {Creator}'s community."

Fanvest Now

What an eligible fan sees on a project that's In Progress. Starts the invest flow (opens a "Choose your plan" bottom sheet). Doesn't appear on Upcoming projects. Note: BRD names this CTA "Join the Journey"; production ships as "Fanvest Now" — see Tab 2.

Cross-role interactions in plain English

For ops triage: these are the touch points where one role's action visibly affects the other.

When this happens It affects Effect
Artist publishes a project Fans see it Project shows up in artist's store under "Fanvestor" once preview date is reached.
Fan joins the artist's community — OR — makes any purchase (incl. $0 / free items) System only Fan earns ≥1 loyalty point and is permanently unlocked to invest in that artist. Instant — no waiting period. A $0 purchase awards 28 points (1:28 ratio).
Fan taps "Fanvest Now" and confirms Artist dashboard Remaining shares drop. % Sold goes up. Fan appears in Top Fans list. No card charged.
Fan upgrades plan Artist dashboard Old Royalty Share slot returns to availability, new one taken. Numbers retally.
Artist posts an update Investors Email + in-app for Milestone Completed/Delayed. Investors-only updates hidden from non-investors.
Artist misses a milestone Artist + Fans System blocks artist from posting "Completed" until they post "Delayed" with a new date. Fans see "X days overdue" badge.
End date arrives Artist + Fans Project flips to Completed or Unsuccessful. On Unsuccessful, that project's investment loyalty points get wiped (eligibility stays).

What's in Phase 1 vs out of scope

Anything in the right column is not built in this phase, but the architecture must support adding it later without rework.

✓ In Phase 1

  • Project creation — the full 4-step wizard
  • Status machine — Draft → Not Started → Upcoming → In Progress → Completed/Unsuccessful
  • Eligibility system — instant unlock via community-join OR any purchase (incl. free), 1-point threshold, permanent flag
  • Invest flow — pick plan, Royalty Shares availability check, shipping, Stripe Future Payment Setup, fan contract
  • Plan upgrade — upward-only
  • Reserved shares — committed but not yet assigned
  • Updates — General + Milestone Completed + Milestone Delayed, with overdue branching
  • Loyalty points — earn on community-join + invest + upgrade; revoke on Unsuccessful project
  • Contracts — fan + artist (display only, not enforced)
  • Admin config — X / Y values, contract templates (EN + zh-TW)

⏳ Phase 2 (deferred)

  • Payment collection — Stripe captures method but never charges in P1
  • Share assignment — shares stay reserved, never assigned in P1
  • Charge retry — retry count, intervals, failure templates
  • Fan contract enforcement — display only in P1, legal force in P2
  • FX settlement model — exact Stripe settlement per currency pair
  • Membership card delivery — only ships post-funding
  • Shipping disputes / refunds / fulfilment failures
  • Inventory reservation — Beamco doesn't reserve physical stock during the campaign
  • Comments on updates — Phase 1 has likes only
  • A/B testing & notification analytics
  • Admin retry settings

4Phase 2 — explicitly out of scope

Direct from BRD "Out of Scope (Phase 1)". Architecture must support Phase 2 layering on without rework.

  • Payment collection — methods captured via Stripe Future Payment Setup but never charged.
  • Share assignment — shares are reserved in P1, assigned in P2 only after Completed + successful payment.
  • Charge retry logic — retry count, intervals, failure notif templates.
  • Fan contract enforcement — shown in P1; legal force from P2.
  • Minimum net collected logic.
  • FX settlement model.
  • Inventory reservation — Beamco does not reserve physical inventory during the campaign.
  • Shipping disputes / refunds / fulfilment failures.
  • Membership card delivery — only after funding (Phase 2).
  • Comments on updates — likes only in Phase 1.
  • Admin payment retry settings.
  • A/B testing & notification analytics.
