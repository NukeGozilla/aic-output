Top of the pile

TL;DR — five things to decide first

The new biz BRD is essentially Phase 1 + the Phase 2 that was deferred + Stage-3 payout/royalty mechanics. Five decisions unblock the rest.

01

Phase 2 collection rolled into the spec

Phase 1 deliberately deferred charging. The new BRD's BR-28 → BR-32 (batch charge + smart retry + manual recovery + waitlist + threshold cancel) is all net-new vs Phase 1 — and a different shape than Ztor v6.

02

Eligibility model rewritten

Phase 1: follow X consecutive days → earn Y LP → permanent flag. New BRD: $1 = 28 LP, join = 1 LP, instant eligibility. Matches the late-April Beamco rework (BR-236).

03

Funding model flips for Beamco

Phase 1 was share-count driven (min required shares, raised = reserved × per-share value). New BRD is amount-based ($5M cap, threshold by %). Ztor v6 is already amount-based — only Beamco needs the data-model migration.

04

Three different status machines

Phase 1 has 5 auto-only states. Ztor v6 has 6 mixed-control. New BRD has 8–9 with a new Funded vs Successful split (target hit vs all charges cleared). Pick one taxonomy before build.

05

Backer reward model diverges

Phase 1 = shares + plan items. Ztor v6 = redeem code → 30-day free viewing. New BRD = cash royalties (≥ USD 50, quarterly). Conceptually different products — pick per content type.

§A — Beamco direction

Phase 1 BRD vs New BRD (Music column)

Where the proposed Music spec breaks with the Phase 1 BRD that's currently approved for Beamco.

Δ-01 Payment collection Phase-boundary
Phase 1 BRD Setup-only
FR-32: Stripe Future Payment Setup only — captures payment method, does NOT charge in Phase 1. Charge is Phase 2 (Out of Scope #1).
New BRD Full collection rolled in
BR-28 → BR-32: Batch-charge on funded. Smart retry (3 days). Manual recovery email (7 days). Waitlist replacement on day 10. Failure-threshold cancel-all.
Δ-02 Eligibility model Already-shipped change
Phase 1 BRD Time + threshold gate
FR-22: Follow artist X consecutive days → earn Y loyalty points → permanently unlock per-artist eligibility. X and Y admin-configurable.
New BRD Instant-on-action
BR-20: $1 spent = 28 LP · Join community = 1 LP · Eligibility = ≥ 1 LP. No X-day wait, no Y threshold. Matches the late-April BR-236 rework already approved.
Δ-03 Funding model Data-model flip
Phase 1 BRD Share-count driven
FR-02 / 37: Total shares + minimum required shares = success threshold. Raised = reserved shares × implied per-share value. Goal expressed in shares.
New BRD Amount-based
BR-1 / 7 / 23 / 32: Goal expressed as fund amount in creator currency. $5M cap. Failure threshold by % of $. Shares = per-plan attribute (BR-12/13).
Δ-04 Status state machine Auto-only → manual + new states
Phase 1 BRD 5 states, auto-only
FR-08: Draft → Upcoming → InProgress → Completed | Failed. All transitions date-driven or threshold-driven. Artists cannot manually change status.
New BRD 8–9 states, mixed control
BR-25 / 26: Draft / Active / Cancelled / Funded / Successful / Unsuccessful (+ In Progress / Released / Unreleased post-payout). Adds manual cancel + new Funded vs Successful split (Funded = target hit at end date · Successful = all charges cleared after recovery).
Δ-05 Plan cancellation & upgrade Feature in flight
Phase 1 BRD Upgrade allowed, no downgrade
FR-38 / 39: Upgrade to higher tier OK. Downgrade NOT permitted. Cancellation NOT permitted. One active plan per fan per project.
New BRD Silent on backer upgrade
BR-22 → BR-25 cover admin-side edit lock + manual cancel-with-refund. No mention of backer-side upgrade/downgrade flow. Either carry the Phase 1 logic forward, or document the regression.
Δ-06 Pledges per fan per project Pick one
Phase 1 BRD One active plan
FR-36: One active plan per fan per project. Upgrading overwrites the previous selection.
New BRD Not addressed
New BRD doesn't restate. Ztor v6 BR-21 explicitly allows multiple pledges per backer. Beamco may inherit Ztor's rule by default — confirm intent.
Δ-07 Milestone update governance Strong rule, drops
Phase 1 BRD Strict governance
FR-13 / 19 / 20: Roadmap date change → mandatory "Notify Users" update (cannot save without). Overdue auto-display. Cannot post Milestone Completed if overdue — must post Milestone Delayed first.
New BRD Music defers, Movies thins
BR-6: Music = milestones not required for MVP. Movies = mandatory but loosely specified (5 max, month+year, optional status updates). The governance rules disappear.
Δ-08 Admin configurability Loses flexibility
Phase 1 BRD Admin-managed
FR-55 / 56: Admin sets X (days) + Y (points) for eligibility. Admin manages contract templates with EN + zh-TW localisation + versioning.
New BRD Hard-coded
LP rate fixed at 28-per-$1; no admin config section. No template versioning or i18n. Per-backer contract PDF mentioned but no template authoring flow.

§C — Cross-cutting

Three different mental models, side by side

Where the same concept gets three different shapes across the three docs.

Project status machine

Phase 1 BRD

5 states · all auto
Draft → Upcoming → InProgress → Completed / Failed.

Transitions date + threshold driven. No manual override.

Ztor v6

6 states · mixed control
live → funded / unsuccessful / canceled; funded → in_production → released.

Ops controls most transitions.

New BRD

8–9 states · mixed control
Draft / Active / Cancelled / Funded / Successful / Unsuccessful + In Progress / Released / Unreleased.

New Funded vs Successful split (target hit vs all charges cleared).

Eligibility / LP model

Phase 1 BRD

Follow artist X consecutive days → earn Y LP → permanent per-artist eligibility flag. X+Y admin-configurable. Eligibility persists even if LP later removed.

Ztor v6

1 LP per joined creator, locked at 1, internal-only, never displayed. Eligibility = ≥ 1 LP on that creator.

New BRD

$1 = 28 LP · Join = 1 LP · Eligibility = ≥ 1 LP · Fans see per-creator LP balance. (Music side gets the visible balance; Movies stays simple for now.)

Currency

Phase 1 BRD

Per-project, locked at publish (FR-11). Allowed set not enumerated. FX settlement model = Phase 2 (OOS).

Ztor v6

HKD or TWD only. Locked Must-Know #4. Other-region viewers see FX preview marked 參考價格.

New BRD

SGD or USD only (BR-16). Music = locked after selection. Movies = editable (TBD what that means).

Share denomination

Phase 1 BRD

Total shares + minimum required shares (success threshold). Plans carry share_count. Goal expressed in shares.

Ztor v6

Goal in creator currency. Only isShareTier: true tiers issue shares. Project-level equityOfferedPct.

New BRD

Goal in creator currency ($5M cap). Music = royalty shares % + count (project-level). Movies = revenue shares % + count (project-level).

§D — Don't lose these

Phase 1 governance rules the new BRD silently drops

Strong rules in Phase 1 that aren't restated in the new BRD. Worth keeping unless explicitly cut.

  • FR-13 Mandatory "Notify Users" update when a roadmap milestone date changes — cannot save the date change without posting it
  • FR-19 / 20 Milestone overdue auto-display + blocking Milestone Completed until artist posts a Milestone Delayed update first
  • FR-08 Status transitions auto-only — artists cannot manually change project status (new BRD's manual cancel partially reverses this)
  • FR-23 / 24 Eligibility flag is permanent even if investment-earned LP is later removed — invariant the new BRD doesn't restate
  • FR-38 Plan upgrade flow (higher tiers only) — backer-side feature in current Beamco, not addressed in new BRD
  • FR-56 Admin contract template versioning + EN/zh-TW localisation — drops
  • "Equity-like shares" regulatory flag — Phase 1's Confidence Note flagged this for legal review in MY/TW/SG/US. New BRD's SGD/USD pivot makes US/SG exposure higher, not lower.

§F — Action

Recommended next steps

1
Decide which side of the Phase 1 / Phase 2 split the new BRD targets.

If it ships as a single release, plan accordingly. If staged, mark which BRs are Phase 1 vs Phase 2.

2
Confirm the currency pivot (HKD/TWD → SGD/USD).

This is the single most-blocking decision. Loop in Susan + Agnes.

3
Lock the LP rate.

New BRD = 28-per-$1 + 1-on-join (matches BR-236 already approved late April). Confirm this is what's in Beamco production today.

4
Reconcile the payment-recovery state machine.

The 3+7+waitlist+threshold flow needs a fresh diagram. Ztor's current state machine at aic-output/ztor-crowdfund-state-machine.html now drifts from the new BRD.

5
Pick the backer reward model per content type.

Redeem-code-for-viewing (Ztor v6) OR cash-royalty-share (new BRD) OR both. Phase 1 sat in between — fans got "shares + plan items," neither cash nor viewing rights.

6
Carry forward Phase 1's strong governance rules.

Milestone delay → mandatory notification (FR-13), overdue-blocks-completion (FR-20), admin template versioning + i18n (FR-56), status transitions auto-only (FR-08). Don't lose these in the rewrite.

7
Close the blocking biz-team questions (§E).

BR-32 threshold value · BR-33 Stripe Connect · BR-16 currency edit semantics · BR-36 Music royalty flow.

8
Treat the new BRD as canonical going forward.

Re-issue Phase 1 + Ztor v6 as deltas off it. Cheaper than keeping three versions in sync.
