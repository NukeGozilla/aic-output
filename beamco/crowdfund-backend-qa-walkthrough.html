P0-3 Home · Fans Package inventory + share deduction
原问题 · Question (Chinese)
每个 package 是否有自己的库存？还是只要 totalRoyaltyShares 够，就允许用户选择任意 package？一个 package 占多份 shares 时，是否同时扣 package 库存和总 shares？
English translation
Does each package have its own inventory? Or is any package selectable as long as totalRoyaltyShares is sufficient? When a package consumes multiple shares, is both package inventory and total shares deducted?
BRD reference
BR-7 up to 3 packages with royalty shares · BR-N4 "remaining" hidden when 0
✅ Confirmed answer
  • Each package has independent inventory
  • totalRoyaltyShares = Σ(package.inventory × package.shares) — locked at publish
  • package.remaining = package.inventory − package.sold (sold = Captured + Authorized; excludes waitlist)
  • sharesSold = Σ(Captured + Authorized package.shares) — waitlist NOT counted
  • progressPercent = sharesSold / totalRoyaltyShares
  • fanvestors = unique users with Captured + Authorized records
  • Release rules: capture fail / refund / forfeit → restore package.sold + sharesSold; upgrade = vacate old, occupy new; waitlist swap = no change to totals

原问题 · Question (Chinese)
同一个用户在同一个 campaign 下，只能有一个有效参与记录吗？用户能不能升级套餐？能不能取消？waitlist 和 pledge 能不能同时存在？
English translation
Can a user have only one active record per campaign? Can they upgrade packages? Can they cancel? Can waitlist and pledge coexist?
BRD reference
BR-7 inherited rules: one active plan per fan per campaign; upgrade allowed; downgrade/cancel NOT allowed
✅ Confirmed answer
  • One active record per user per campaign
  • Valid record states = Authorized | Captured | Waitlisted
  • Waitlist DOES occupy the unique slot — user cannot pledge Package A + waitlist Package B at the same time

P0-10 PC/Finance Payment Breakdown formulas ⚠ Pending Susan/Finance
原问题 · Question (Chinese)
Total Pledged、Successfully Charged、Unsuccessfully Charged、Payment Fee、Platform Fee、Final Amount、80% / 20% 分别怎么算？
English translation
How are Total Pledged, Successfully Charged, Unsuccessfully Charged, Payment Fee, Platform Fee, Final Amount, and the 80% / 20% releases each calculated?
BRD reference
BR-40 Overview payment breakdown · BR-41 4% payment fee + 5% platform fee · BR-35 Spotify URL + Release Fund
✅ Confirmed answer
  • All amounts displayed in creator settlement currency (SGD/USD, locked at publish per P0-2)
  • FX conversion at charge time via Stripe native cross-currency (BR-16 + O12 closed)
  • Same-currency case (e.g., SGD fan → SGD creator): no FX, 1:1
  • Cross-currency case (e.g., TWD fan → SGD creator): Stripe converts at capture, rate snapshotted per charge
  • Total Pledged (pre-capture display): convert using current FX rate as display estimate
  • Successfully Charged: actual Stripe-converted amounts (post-capture, exact)
  • Unsuccessfully Charged = Total Pledged − Successfully Charged
  • Payment Fee = Successfully Charged × 4%
  • Platform Fee = Successfully Charged × 5%
  • Final = Successfully Charged − Payment Fee − Platform Fee
  • Initial Release = Final × 0.80; Final Release = Final × 0.20
  • Refunds reduce Successfully Charged retroactively
  • Round to 2 decimals
⚠ Needs Susan / Finance to confirm: fee base (gross vs charged amount) · rounding direction · pre-capture FX display rate source (Stripe published rate? daily snapshot?)
