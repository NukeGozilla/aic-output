What the order record stores (reporting fields from the ticket)

Dev delta (Option 2)

Data model — promo_code

  • discount_type enum percent | fixed (today: percent only)
  • discount_value decimal (today: rate %)
  • applies_to enum all | items, default all
  • promo_code_items (promo_id, product_id / ticket_type_id) — empty when all
  • max_redemptions int nullable · redemption_count int

Checkout rule — enforce server-side at order creation

  • Code active in window, case-insensitive, one code per order (existing)
  • Eligible lines = all lines if all, else lines whose item ∈ promo_code_items
  • No eligible line → reject: "Promo code is not valid for items in your cart."
  • percent → Σ eligible line totals × rate · fixed → min(value, Σ eligible line totals)
  • Cap → reject when redemption_count ≥ max_redemptions: "Sorry, promo code has met capacity." · increment on paid order
  • Bundle = its own SKU: eligible only when explicitly selected

Platform fee — separate ticket, platform-wide

  • platform_fee = (subtotal − discount) × rate — changes the basis for every shop, not just LAYYI → needs effective date, forward-only
  • Order stores: original subtotal · code · discount amount · post-discount subtotal · fee

Decide before build

  • Fixed amount: once per order (shown here) vs per unit
  • Rounding: 2 dp half-up, or whole-dollar (Dan's ID-02)
  • Fee rate 5% vs 10%
