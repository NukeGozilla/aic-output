⚠ Deprecated 2026-05-29 · archived for history
This range-threshold solution has been scrapped. BR-N2 (min/max goal range), BR-N3 (pre-end auto-flip on min), BR-N4 (buffer-absorbed FIFO refill), and BR-N5 (smallest-tier validation) were all removed in the 2026-05-29 BRD revision. The current model is share-based: single funding target ($), total royalty shares, and a minimum-royalty-shares success threshold (matches UAT). Goal Achieved fires when all shares are sold; a new Minimum Met status covers end-date-with-min-met-but-not-all-sold. This page is retained for context only — do not use it as a spec source.

(Archived) Admin Campaign Create → Target Selling Price & Quantity. Range-threshold model, 2026-05-27 — superseded by share-based model 2026-05-29.

⚠ Why we're changing it

Fixed target makes waitlist refill impossible to balance

A single number for "Funding Target" means the campaign succeeds only at exactly that amount. When captures fail and we backfill from waitlist, the math rarely lands clean.

Today · Fixed $20,000 target

1,000 backers × $20 = $20,000

  • End date: 50 captures fail → collected = $19,000
  • Need to backfill $1,000 from waitlist
  • Waitlisters pledged mixed tiers ($20 / $50 / $200) — no clean way to total exactly $1,000
  • Pull next 50 FIFO: totals $1,400 → overshoot to $20,400
  • Hand-pick 50 = $1,000: ops becomes a manual matching puzzle, breaks FIFO fairness
Stuck: hit exactly · break FIFO · or overshoot.
Range $18,000–$20,000 · success line at $18K

Same 1,000 backers × $20

  • End date: same 50 fail → collected = $19,000
  • $19K already past the $18K success line — campaign already qualifies
  • Pull waitlisters pure FIFO — no amount-matching, no skip logic
  • Final lands anywhere ≥ $18K → Successful
  • Pledging stays open through end-date — no early-capture, no hard close
Tolerance window absorbs variance · FIFO stays fair.
  • (max − min) buffer is the tolerance window for recovery
  • BR-31 simplifies — no amount-matching
  • BR-32 becomes mechanical — collected ≥ minGoalUsd = Successful
  • BR-N5 caps smallest tier ≤ 50% of buffer so refill always has a workable tier

New BRs What this wireframe implements

BR-N2
Goal as min/max range
  • Replaces single goalUsd
  • minGoalUsd + maxGoalUsd locked at publish
  • Min = success threshold · Max = displayed stretch goal
BR-N3
Pre-end-date Goal Achieved
  • Auto-flips when raised ≥ minGoalUsd
  • Pledging continues until end-date · no hard cap
  • Status history logs trigger amount
BR-N4
FIFO waitlist refill
  • Pure FIFO · amount-agnostic
  • Buffer absorbs variance
  • Refill until failed slots resolved or queue empty
BR-N5
Smallest tier ≤ 50% of buffer
  • Smallest tier price ≤ (max − min) × 0.5
  • Guarantees a usable filler tier exists
  • Single-tier campaigns: rule applies to that tier
