Decisions (BRD v5.2 · 2026-05-08)

  • Eligibility = join Creator’s community — user holds 1 LP per joined creator (non-cumulative); that LP gates pledge action. Replaces both prior POPCORN-purchase and follow-based models. Wording rename: 追蹤 → 加入社群 platform-wide for crowdfund flow. LP is internal only; not surfaced to backers.
  • Funding model = amount-based with package-specific shares — only isShareTier tiers issue shares (shareUnits per lot). Non-share tiers contribute to goal but issue zero shares. Creator sets equityOfferedPct (% offered to backers; creator keeps the rest). Per-tier cap controls oversubscription: cap = 0/blank → unlimited; cap > 0 → closes at cap.
  • Stripe Future Payment — no charge during pledge; batch capture on Funded transition in creator currency at Stripe daily FX rate (decimals OK).
  • Backer reward = redeem code for free viewing — unique one-time code per pledge on Released; 30 days to activate, 48 hours to finish; no POPCORN charge.
  • Physical fulfillment in scope — project-level collectsAddress toggle; ops handles manual shipping (順豐 / similar) and bulk-imports tracking; creator absorbs shipping cost (priced in tier).
  • Platform fee model — deducted from creator income (e.g., backer pays 1000 → creator nets 950). Funding-plan fee HK$75K one-off baseline. All costs (including shipping) computed before charge.
  • Comments + moderation — required; admin tool can soft-delete inappropriate content.
  • Project announcements via post-mention — sourced from Ztor social posts mentioning the project (BR-22). Manual project-level announcements deprecated.
  • No Creator Studio for May launch — all creator setup is offline via /admin. Plan to port AIC CMS Timeline editor for creators in a later phase.
  • Cancel during funding NOT allowed in Simple v · refunds only for special creator-default cases via Finance + Stripe back-office. Taiwan 鑑賞期 legal still pending Sam (now non-blocking — see open list).
  • Pledges are private — only self-visible on the user’s profile. Same backer can pledge multiple tiers (per-tier qty cap).
  • SKU options out of scope for May — product variants (size/color) handled offline initially.
  • 收藏 (bookmark) feature — not in scope for Simple v (Q8 closed 2026-05-08). Revisit Stage 3 based on user feedback.

Open items — current (Q1–Q7, all 🟡 non-blocking; prototype implements a default, ops sign-off pending)

  • Q1 TW 鑑賞期 / cooling-off — Sam (legal). Prototype keeps "no cancel during funding" (2025-10-27 decision); add cancel flow if Sam confirms TW law overrides.
  • Q2 Funded / Unsuccessful definition — Agnes. Prototype: no minimum backer count; success = raised >= goal only.
  • Q3 Share-count cap — Susan + Agnes. Prototype: no platform-level cap; per-tier cap × shareUnits is implicit ceiling.
  • Q4 Tier cap & oversubscription — Susan + Agnes. Prototype: per-tier rule (cap = 0/blank → unlimited; cap > 0 → closes at cap). No project-level toggle.
  • Q5 Equity offered % — Susan + Agnes. Prototype: creator inputs equityOfferedPct; platform doesn’t enforce share-unit-to-% mapping.
  • Q6 Community-exit handling — Ops. Prototype: user can exit; LP is NOT removed; existing pledges stay valid.
