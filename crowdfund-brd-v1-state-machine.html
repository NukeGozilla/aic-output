State definitions

WHAT EACH STATE MEANS AND HOW THE CAMPAIGN BEHAVES WHILE IT'S IN THAT STATE

Draft

Campaign being configured. All fields editable. Not visible to fans. Can be deleted.

Pre-publish · Internal only

Active

Campaign published and live. Fields locked. Fans browse + pledge (card locked, no charge). Edit lock per BR-23. Waitlist opens when shares sell out (BR-4).

Live · pledges open

Goal Achieved

All royalty shares sold (sharesSold == totalRoyaltyShares) — fires the moment the last share is pledged, may be pre-end-date. Pledging closes; waitlist absorbs new sign-ups. Batch-charge (BR-28) fires on end-date. Recovery loop runs on declines (BR-29 / BR-30 / BR-31). Renamed from "Funded" (2026-05-25) · trigger updated 2026-05-29 to share-based (all sold).

Transitional · charging

Minimum Met ★ NEW 2026-05-29

End-date reached with sharesSold ≥ minRoyaltyShares but < total. Campaign cleared the threshold + moves forward. Same downstream as Goal Achieved (batch-charge → recovery → BR-32 check). Distinct from Goal Achieved because not all shares sold — used in reporting + fan-facing copy ("project cleared the minimum threshold").

Transitional · partial sell-through

Unsuccessful

Two paths in: (a) end-date with sharesSold < minRoyaltyShares (zero charges fired, no refund needed); (b) post-recovery from Goal Achieved or Minimum Met where finalSharesPaid < min (refund all charged backers via Stripe back-office). Terminal.

Terminal · stop / refund-all

Successful

Mechanical BR-32 check passed: finalSharesPaid ≥ minRoyaltyShares after recovery. First tranche (80% minus 4% payment fee + 5% crowdfund platform fee) released to creator wallet automatically. No ops review gate — share-based threshold is deterministic.

Money moved · first tranche · 80%

In Progress

Creator producing work. Status updates allowed (creators can post throughout, per BR-27). Awaiting final product URL submission to trigger Released.

Production window

Released

BR-35 two-step: Step 1 ops submits Spotify URL → "Release Fund" button surfaces in back office → Step 2 ops clicks. Second tranche (20%) released to creator wallet. Triggers N13 release email to backers. Royalty reporting (BR-36) ships as display-only / non-functional in MVP.

Terminal · 20% paid · royalty active

Cancelled

Reached from Active, Goal Achieved, Minimum Met, or In Progress. All backers refunded (via Stripe back-office, manual). Listing retained with Cancelled status. Triggers N11 cancel email. Terminal.

Terminal · refund-all

Fan Order State Machine

PER-FAN, PER-PLEDGE — DISTINCT FROM THE CAMPAIGN STATE MACHINE ABOVE

Each fan's pledge runs through its own lifecycle — independent of the campaign state. Two fans on the same campaign can be in different order states at any time (one Charged, one Failed retry, one Refunded). The UI shows both pills together — order state (what's happening with your money) and campaign state (what's happening with the project).
