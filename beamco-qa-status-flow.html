What changes Adopt

  • Add (or formalize) Testing as the active-pickup state between UAT and outcomes.
  • Pilot on Beamco only first — Ztor already has 2 tickets in Testing organically; let it stay until Beamco proves the pattern.
  • Daily QA discipline: dev sets UAT unassigned · tester self-assigns + moves to Testing · resolves to Launch Ready or Test Failed.
  • Re-test loop standard: Test Failed → Development → Fixed → UAT → Testing.

What to clean up Retire

  • Copywriting as a status — captured by section/parallel work, near-zero usage.
  • Discussion as a status — overlaps with Asana comments + triage.
  • Reconcile Development ↔ Ready For Development — Beamco uses the latter; the former sits unused.
  • Retire Beamco section "Testing (QA/UAT in test env)" — duplicates the new status.
  • Confirm Launched = deployed, Done = verified-in-prod (or merge them).

What to watch Risk

  • Status field discipline — Ztor has 33% null on the primary status field. New status won't help if field isn't filled.
  • Multiple Status fields exist — Beamco has 3 GIDs, Ztor has 4 (Pawkit's is separate). The "shared across 11 projects" model is partial.
  • Section-vs-status confusion — Beamco encodes UAT cycles in section names (e.g. "UAT April 27 - 28"). Pick which layer carries which signal.
  • Capacity, not workflow — 56 in UAT is a queue depth issue. The status helps measure it but doesn't shrink it; that's Ming's job.

Three open questions for the team

  • Re-test path: after Test Failed → does it route through Fixed or skip it?
  • Launched vs Done: two states or one? Recommend deployed vs verified-in-prod split.
  • Pending meaning: blocked, deferred, or waiting on input? Pick one — currently overloaded.
