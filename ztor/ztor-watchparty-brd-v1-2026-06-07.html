Scope note — what this is NOT
No Twitch iframe player, no Twitch-native chat (both dropped per Jeff). Video is served from Ztor's own CDN (HLS/DRM); chat + sync + presence run on our self-built Ably stack. Voice chat is out of scope (optional fast-follow via LiveKit/Daily).

User stories
US-01As a host, I want to start a watch party from a title page and share a link, so others can join my session.
US-02As a guest, I want to join with a link and be let in only if I'm registered and have paid, so the room stays valid and licensed.
US-03As a viewer, I want playback to stay in sync and to chat with emojis beside the video, so it feels like watching together.
US-04As a guest, I want to leave and re-enter the same room freely, so a dropout doesn't end my night.
US-05As ops, I want to cap room size and enforce regional licensing, so we protect capacity and rights.
US-06As the business, I want watch-party engagement measured, so we can value co-watching against normal viewing.

BR-01Host creation (premium-gated). Premium users SHALL launch a room from the player and receive a shareable link/code.MUSTTO BUILDOpsDesignArchNeeds Ztor backend permission to launch. Demo stubs this.

BR-03Per-room capability token. Ably tokens SHALL be scoped to one room — publish on video-{room} for host only, subscribe-only for guests.MUSTTO BUILDArchOpsDemo uses a broad key + client host flag; prod asserts host from room record.
BR-04Geoblocking. System SHALL enforce regional licensing at the video/entitlement layer. F《我要衝線》 = worldwide; imported titles SHALL be geoblocked.MUSTREUSEOpsDesignArchEnforced at CDN/manifest, not Ably. Reuse Ztor playback authz.
BR-05Participant cap (dynamic). System SHALL enforce a per-room member limit, adjustable on the backend per campaign.SHOULDTO BUILDOpsNet-new (not in diagram). Check presence occupancy before issuing token.
