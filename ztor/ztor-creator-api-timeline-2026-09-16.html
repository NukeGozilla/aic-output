Who owns the public gateway and checkout?對外閘道與結帳歸誰？

06Option B — lloud.club integrates Open Loyalty directly選項 B——lloud.club 直接串接 Open Loyalty

Plan A routes loyalty through Ztor: Open Loyalty → Ztor → release 4 → lloud.club, live on lloud.club Dec 7. Option B: sign the Open Loyalty contract by Oct 9, start integration Oct 12, and let lloud.club call Open Loyalty directly while Ztor does its own integration in parallel. Loyalty is live on lloud.club Nov 13, a week before release 4 and 24 days before Plan A. Two specs make it safe: how the direct integration works, and how it merges back into Ztor later. 方案 A 的積分經 Ztor 中轉：Open Loyalty → Ztor → release 4 → lloud.club，lloud.club 於 12/7 上線。選項 B：10/9 前與 Open Loyalty 簽約、10/12 開始串接，lloud.club 直接呼叫 Open Loyalty，Ztor 同時做自己的串接。lloud.club 積分 11/13 上線，比 release 4 早一週、比方案 A 早 24 天。需要兩份規格把它做穩：直接串接怎麼做，以及之後怎麼併回 Ztor。

spec 1 · direct integration
How lloud.club talks to Open Loyalty without Ztor in the middlelloud.club 如何不經 Ztor 直接與 Open Loyalty 溝通
Identity: member id = Ztor user id, created by Ztor at sign-in. One writer of points: Ztor posts order and refund events (orders live in Ztor eShop); lloud.club only reads balance, ledger, tier, rewards and submits mission proofs. Credentials: per-member tokens from Open Loyalty's customer API, or a thin Ztor proxy; never the admin key in a browser. Sync-back: Open Loyalty → Ztor webhook (points, tier) into the Policy service for gating and the Media Vault. Owner: Jeff · Nan with Eric, written Oct 12–16 against the vendor docs.身分：會員 id＝Ztor user id，由 Ztor 於登入時建立。唯一寫入方：Ztor 送出訂單與退款事件（訂單在 Ztor eShop）；lloud.club 只讀餘額、帳本、等級、獎勵，並提交任務證明。憑證：Open Loyalty 客戶端 API 的會員 token，或 Ztor 輕量代理；絕不把 admin key 放在瀏覽器。同步回寫：Open Loyalty → Ztor webhook（積分、等級）進 Policy 服務，供購買限制與媒體庫。負責：Jeff · Nan 與 Eric，10/12–16 依供應商文件撰寫。
spec 2 · merge back to ztor
How lloud.club moves onto release 4 later without losing anythinglloud.club 之後如何無損改接 release 4
No data migration: both paths use the same Open Loyalty program, member ids and ledger, so the merge is a client switch, not a data move. Cutover: a per-channel flag in api-client.js swaps the loyalty endpoints from Open Loyalty to the Creator API; run both read paths for a week, compare, then retire the Open Loyalty tokens. Ops: LLOUD loyalty administration moves from Open Loyalty's admin into Creator Studio at cutover. Owner: Jeff · Nan with Eric, written Nov 9–13; cutover Dec 7–18.不搬資料：兩條路徑用同一個 Open Loyalty 方案、會員 id 與帳本，併回只是切換客戶端，不是搬資料。切換：api-client.js 內的 channel 旗標把積分端點由 Open Loyalty 換成 Creator API；雙讀一週比對後，回收 Open Loyalty token。營運：切換時 LLOUD 積分管理由 Open Loyalty 後台移到 Creator Studio。負責：Jeff · Nan 與 Eric，11/9–13 撰寫；12/7–18 切換。
