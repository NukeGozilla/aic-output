Alternative B — Ztor is the entrance, Bookyay is the store

Standalone tickets: buyer completes purchase on Bookyay — shown as an overlay checkout styled like Ztor (not a new tab; Eric confirms feasibility) · no Bookyay account needed: the buyer stays a logged-in Ztor user whose data passes through with the order, recorded on Bookyay as a Ztor-flagged buyer. Bundles: Bookyay allocates a fixed ticket block to Ztor; Ztor sells ticket + merch bundles through its own checkout. Raised in the 08-13 core standup — reopens O4 · drafted for biz review by Wed Aug 19.

B1 · Buyer Flow
Browse events on Ztorlisting · artist eShop · homepage
Bookyay checkout in overlayBookyay URL behind a Ztor-styled frame — provider contracts intact
Pay on Bookyayno Bookyay login — Ztor identity + buyer data pass through · QueueIt · block list · limits all enforced
E-ticket issuedorder on a Ztor-flagged buyer record · loyalty auto-attributed · delivery channel → B6
Bundle (unchanged Ztor flow): Bookyay allocates a fixed block (e.g. 100) → Ztor sells ticket + merch as one purchase → e-ticket in My Wallet · merch ship / QR. Ztor sells "as if it already bought the tickets" — the vendor-allotment model Bookyay already runs with partners today.
B2 · What this makes free
1Provider-locked contracts solved — checkout stays on Bookyay's signed URL; no legal / contract work
2Money in one account by construction — standalone ticket money lands directly in Bookyay's provider account; no reconciliation or chargeback split
3Account problem dissolves — no Bookyay signup: buyer data passes through with the order; Bookyay records a Ztor-flagged buyer; block list still enforced at checkout
4No QueueIt second-domain licence — spikes stay on Bookyay's protected rails
5Bookyay promotes Ztor — overlay purchases auto-attribute loyalty (Ztor id rides with the order) · "Connect your Store account" + Store SSO covers buyers on Bookyay's own site
6Ztor build shrinks — event browsing + bundles + SSO only; frees October capacity (Easter-egg campaign, VIP loyalty) · Creator Studio permanently = import + mapping + bundles (no event-mgmt migration, ever)
