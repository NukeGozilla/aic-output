S5 · Kickoff Agenda — 5 gate decisions · must leave the room decided
G1

Standalone checkout model

Decided — native on ZtorRedirect to Bookyay rejected by the biz team; the buyer never leaves Ztor. All ticket sales run on Ztor checkout via the Bookyay API (flow in S3a).
Room acknowledges: P2 spike protection + hold/commit API (P1) + MoR over all Ztor sales (G5) are now Phase-1-critical
G2

Bundle ticket inventory

For discussion — two options, sequenced on P1 auditOpt 1 — shared live pool via real-time hold/commit API (single source of truth · Bookyay purchase limits apply) · Opt 2 — allocated block + release-back (fallback / per-event exclusive inventory)
Axis: G1-native already requires hold/commit for standalone — shared pool adds little extra API depth, making Opt 1 the natural lean; Opt 2 stays as schedule fallback / per-event exclusive blocks. A check alone can't prevent pay-then-fail races — hold → pay → commit.
