● Design Proposal · Sprint 1.16.2

AIC CMS — Save this step.
Not a draft system.

Per the 4/30 dev sync: don't build a separate "draft" feature. Add an inline 儲存此步驟 / Save this step button to every step of the existing 5-step contest creation wizard. Editors stop losing work to forced logouts and tab-closes without learning a new flow.

Ticket: [AIC] CMS - 儲存草稿功能 Owner: Eric Tam Target: May 11 Effort: ~4 dev-days

01The problem

Editors lose work when they get force-logged-out or the edit page auto-closes during a long contest creation. Today, the only way to persist anything is the final 創建活動 button — which requires every required field across all 5 steps to be filled.

Before Today's flow
  • 5-step wizard, ~230 inputs total
  • Step 1 alone: 84 inputs + 9 image uploads + 4 rich-text editors
  • 下一步 / 上一步 are pure client-side toggles — no network call
  • 創建活動 is the only persistence path; fails if any required field is missing
  • No "last saved" indicator, no draft state, no recovery after logout
  • Tab close or session expiry → all in-flight work lost
After Proposed
  • Same 5-step wizard — no new screens
  • Each step gets its own 儲存此步驟 button (blue, primary)
  • Saves a partial contest as status='draft' — required fields not enforced until publish
  • Header shows live save state: ● 已儲存 · 1 分鐘前
  • Saved steps get a green ✓ in the wizard nav
  • Re-entry after logout lands on the last saved step with all data restored

03Save-state taxonomy

The header pill is the at-a-glance signal. Five distinct states, each combining color + text + icon (color is never the only signal — passes WCAG).

未編輯

Pristine

Pill hidden. New contest, no input yet.

未儲存的變更

Dirty

Editor changed a field. Strong amber nudge.

儲存中…

Saving

Network in flight. Button locked, spinner.

已儲存 · 剛剛#5

Saved

Persisted. Timestamp counts up: 剛剛 → 1 分鐘前 → 5 分鐘前.

儲存失敗，重試

Error

Clickable. Form state preserved on retry.

04Save button — visual spec

06Implementation — ~4 dev-days

Each step is already a separate <form> in the DOM (verified). Per-step save is a thin layer over what's already there.

Day 1

Backend: status + partial endpoint

Add status, last_saved_step, last_saved_at columns. Build PATCH endpoint that accepts partial step data.

Day 2

Backend: publish endpoint

Move full validation behind a separate POST /publish route. Existing rows backfilled to status='active'.

Day 3

Frontend: Save buttons + JS

One button per <form>. Submits FormData to PATCH endpoint. Handles loading / success / error states.

Day 3.5

Frontend: pill + step ✓

Header save-state pill, step-indicator checkmarks, dirty-tracking on input/change events.

Day 4

QA + edge cases

Verify re-entry after logout, browser refresh warning, partial-save with required fields blank, multilingual content (繁中 / English).

Out of scope (separate ticket): the underlying force-logout / page-auto-close bug. This design mitigates damage from logouts — it doesn't prevent them.
