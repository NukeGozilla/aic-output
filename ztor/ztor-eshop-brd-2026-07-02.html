01 Why · Target

  • Beamco artists' merch storefronts need a durable home as Beamco 1.0 → maintenance (~80% of eng shifts to Ztor 2.0 Creator Studio).
  • Ztor (film/OTT rental, no commerce today) needs a creator-commerce surface for Creator Studio + the "Follow the Money" vision.
  • Approach: wrap the existing Beamco commerce module (multi-tenant; Ztor is a named tenant) as a microservice — reuse, not rebuild.
  • Target: end-August MVP1 — internal-ready mid-August · launch end-August. (Per the 2026-06-24 MVP1 decision: Phase-1 = end-August.)

05 FE Buyer storefront (scope IDs B01–B10)

  • B01 Creator shop page — storefront is the creator profile Shop tab (/shop/:handle); tabs for 商品 / 套組 / (拍賣 deferred).
  • B02 Product detail (PDP) — gallery, variants/size, qty, add-to-cart, delivery/returns line, related rail. (Built on Frontend@L.)
  • B03 Cart — slide-over drawer, line items, qty±, subtotal/shipping.
  • B04 Checkout — single-screen review (address, shipping method, payment, promo, tax), login-gated.
    • B05 Card / Apple Pay via Stripe (fiat).
    • B06 Pay-by-POPCORN (net-new tender) — gated on OQ-1.
    • B07 COD — removed from Phase 1.
  • B08 Order confirmation — success + order number + status tracker → My Orders.
  • B09 Pickup QR (display) — P1, primary fulfilment. Static QR (email + order detail) for on-site pickup goods. (Today built for tickets — must extend to goods.)
  • B10 Public discovery rails — /shops + home product rails — P2, CMS-curated, Published only.

06 CS Operator / Creator Studio (scope IDs S/O/E)

6.1 Shop management (S01–S50) — /e-shop

  • Product list: columns, status filter (Live / Hidden / Low stock / Sold out / Draft), low-stock alert bar, per-row Shop on/off + edit + restock.
  • Create product: media, info, variants (single/multi → SKU/cost matrix), dual price (cash + POPCORN †), inventory (unlimited/limited + threshold), fulfilment = Shipping or on-site QR pickup, purchase limit + tags, preview, Save draft / Start selling.
  • Bundles: ≥2 member products, fixed or %-off price, stock = min(member).
  • Restock flow (alert / row / detail) → Restocking → Mark received.
  • Product detail: sales summary (read from Earnings), see-as-fan preview.

6.2 Orders (O01–O24) — /orders

  • KPIs (To-ship / Pending / Refund-dispute / Completed-30d), search, status filter, export.
  • Order detail: line items, buyer info, amount breakdown read-only — source = Earnings (goods · shipping · platform fee · payment fee · net).
  • Fulfilment: manual shipping (ops enter carrier + tracking → Mark shipped ‡) or QR pickup (O24 · scanner — operator scans buyer's pickup QR → 核銷 → 已取貨). Refunds/disputes deferred (money impact handled in Earnings).

6.3 Earnings (E01–E24) — the money source of truth — /earnings

  • Overview: Gross · Net · Pending · Available. Transactions with source filter (eShop tab in scope; other revenue tabs deferred). Export CSV.
  • Orders display amounts but never recompute — Earnings owns the numbers.
  • Deferred: revenue-breakdown waterfall (blocked on platform-cut, OQ-4), payout, tax docs, manual entry, charts.

6.4 Store settings — /store-settings

  • Identity (name, bio, logo/cover), URL slug ztor.com/shop/{slug}, currency; product display order; Stripe status read-only; shipping defaults (ship-from, free-ship threshold); see-as-fan.

† POPCORN-as-tender → OQ-1. ‡ manual shipping is offline/no-carrier → OQ-3.

11 Scope guardrails · Dependencies

✓ Do

Reuse Beamco commerce as a tenant (not a fork) · keep cash as price-of-record (POPCORN derived) · reuse the profile/tab + CMS-block patterns · Earnings owns money, Orders display it.

✕ Don't (v1)

No standalone "create shop" (side-effect of creating a creator) · no Draft on any public surface · no admin global cross-creator view (always role-assume) · no in-system refunds · no carrier/logistics integration (manual ship by hand is fine in P1; carrier API = Sept) · no non-physical SKUs · never present POPCORN as "buying tokens".

⚙ Depends on

Commerce module wrapped as a microservice (gateway owned by Beamco team) · Ztor identity + creator_profile · Stripe (fiat, phase-1) · POPCORN ledger · pickup-QR service (blocker) · CMS Content Blocks · Posts service · carried-over Beamco shop UAT bugs.
