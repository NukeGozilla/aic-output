Three questions, answered per field: ① Pull it from Bookyay? ② Where does Ztor use it (FE buyer pages / CS admin)? ③ Who is the authority (feed-locked / feed · override allowed / Ztor-owned)?

Legend 圖例 — Authority 權威 (rule source: BRD v1.3 BR-10 / §6b)

One test decides every row: if the ticket, venue scan, money, or lifecycle depends on the field → Bookyay-owned, locked (an override would make the buyer’s ticket disagree with the systems that validate it). If it only affects how the Ztor page looks → Ztor-side. Ruled 09-10 (Option 4, "add, never edit"): no overrides — every feed field locked; Ztor adds images / supplementary text / translations in a separate display layer. Only sign-off left: flag fields NOT to send. Revised 09-16: two exceptions — event name editable (mixed EN/ZH + sponsor titles) · images always re-uploaded on Ztor; list may grow with the FE prototype.
判準只有一條：票券・掃描・金流・生命週期依賴的欄位 = Bookyay 鎖定；只影響 Ztor 呈現的 = Ztor 側。09-10 定案「新增不改」：feed 欄位全鎖、無覆寫；Ztor 顯示層新增圖片／補充文案／翻譯。09-16 修訂：唯二例外 — 活動名稱可覆寫（中英混排＋冠名）、圖片一律 Ztor 重新上傳；例外清單隨 FE 原型定稿可能增列。
ValueMeaning
feed-locked feed 鎖定Bookyay is the source of truth. Ztor shows the value read-only; every hourly sync overwrites it. Never editable on Ztor.
feed · override allowedRe-scoped 09-16 — applies to exactly one field: event name (mixed EN/ZH + sponsor titles). An overridden name stops following the feed; one-click revert. Every other feed value stays locked ("add, never edit").
Ztor-owned Ztor 自建Never comes from Bookyay (section E).
—Not pulled or not shown, so no authority applies.
