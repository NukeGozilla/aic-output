Bookyay → Ztor Event Field Mapping (draft — for biz / Jesse to confirm)

2026-09-08 · English version 2026-09-09 (legend added from BRD BR-10) · from the 09-08 standup (CS already covers most Bookyay fields; FE not yet aligned) · parent rule: BRD v1.3 §6b / BR-10 · tick row by row at the 09-09 meeting

Three questions, answered per field: ① Pull it from Bookyay? ② Where does Ztor use it (FE buyer pages / CS admin)? ③ Who is the authority (feed-locked / override allowed / Ztor-owned)?

Legend 圖例 — Pull? 拉取

ValueMeaning
Must pull 必拉Required for Phase 1 — a Ztor surface depends on it
Recommended 建議拉Useful now or soon; not blocking
Optional 可略May be skipped; harmless if pulled and unused
Reference only 拉作參考Pulled to help the admin, never shown to buyers
Do not pull 不拉Out of Phase 1 scope

Legend 圖例 — Authority 權威 (rule source: BRD v1.3 BR-10 / §6b)

ValueMeaning
feed-locked feed 鎖定Bookyay is the source of truth. Ztor shows the value read-only; every hourly sync overwrites it. Never editable on Ztor.
feed · override allowed feed，可覆寫Bookyay supplies the default value. A CS admin may override it for Ztor UI needs. An overridden field stops tracking the feed; one-click revert restores the feed value. Only three fields qualify: display name, description, lineup display.
Ztor-owned Ztor 自建Never comes from Bookyay (section E).
—Not pulled or not shown, so no authority applies.

Bookyay → Ztor 活動欄位對照（草案，供 biz / Jesse 確認）

2026-09-08 · 依據 09-08 standup（CS 已涵蓋多數 Bookyay 欄位；FE 尚未對齊）· 母規則 BRD v1.3 §6b/BR-10 · 供 09-09 會議逐列打勾

三個問題，逐欄位回答： ① 要不要從 Bookyay 拉？ ② Ztor 端用在哪（FE 買家頁 / CS 管理）？ ③ 誰是權威（feed 鎖定 / 可覆寫 / Ztor 自建）？

A · 基本資訊

欄位拉取？Ztor 用途權威備註
event id必拉對帳鍵（匯入 / 回寫 / 作廢）feed 鎖定同一場只帶入一次的鍵
活動名稱必拉FE 卡片+詳情 · CSfeed，可覆寫顯示名稱BR-10
活動類型必拉FE 分類篩選 · CS 標籤feed 鎖定Ztor 端對應到 FE 三分類；線上演唱會 / Watch Party 歸屬 = 週三決策 #4
描述必拉FE 詳情feed，可覆寫Ztor UI 版面不同（09-08：欄位調整以符合 UI/UX）
主辦方名稱必拉CS 對應創作者的線索feed 鎖定無 creator 檔案 — 僅文字
Lineup / 表演者必拉FE 詳情feed，顯示可覆寫Ztor 用戶連結 = Ztor 側自建
系列 / 場次序建議拉FE 場次選購 · CSfeed 鎖定09-08：多場次選購是 FE 需求

B · 時間與地點

欄位拉取？Ztor 用途權威備註
活動日期 + 開演時間必拉FE · Wallet · 通知feed 鎖定變更 → 通知購票者（BR-42）
開放入場（doors）必拉FE 詳情 · 票面feed 鎖定票面與通知顯示
結束時間可略——FE 不顯示可略；拉了不用也無妨
場地名稱 + 城市必拉FE 卡片+詳情feed 鎖定
完整地址建議拉FE 詳情（地圖連結）feed 鎖定

C · 視覺素材

欄位拉取？Ztor 用途權威備註
Bookyay 圖片拉作參考CS 設定時預覽—正式素材一律 Ztor 重新上傳（版位規格 2:3 / 16:9 / 圖庫，BR-10）
影片預告可略——Ztor 端如需，自行上傳

D · 票務（核心）

欄位拉取？Ztor 用途權威備註
allocation 數量必拉CS 唯讀容量feed 鎖定MVP = 整場庫存（take-all）；增減隨 feed
票種結構（名稱/價格/數量）必拉CS sale_item 基礎 · FE 票區feed 鎖定票價幣別 = 週三決策 #3
各票種販售時窗必拉FE 開賣/停售 · CSfeed 鎖定09-08 確認：Bookyay 原生支援逐票種時窗 — 不需要「同活動開兩頁」的變通
預開 QR payload必拉Wallet 出票feed 鎖定BR-02/30
活動狀態（售票中/取消…）必拉FE + CS 生命週期feed 鎖定取消 → 自動下架+作廢（BR-43）
座位圖 / 劃位不拉——Phase 1 僅 GA（§3）

E · Ztor 側自建（不從 Bookyay 來）

  • creator_mapping（逐場對應，發布閘門）· sale_items / reservations（單賣+套組）· 套組周邊 SKU（eShop）
  • FE 分類標籤與排序 · 顯示幣別價格（Ztor 幣別模型）· Ztor 上架窗口（可見性）
  • 覆寫欄位的值（名稱/描述/Lineup 顯示）· Ztor 版位圖片

給會議的三個確認

  • 1. Bookyay 欄位清單以上表為準逐列打勾（Jesse 補我們漏掉的欄位）
  • 2. FE 原型缺的欄位（場次選購、doors、逐票種時窗）→ 花花/設計負責人調整（09-08：FE 主要工作 = 欄位調整）
  • 3. 「可略」欄位確認可略 — 少拉一欄就少一個同步面
