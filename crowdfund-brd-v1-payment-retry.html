New Beamco Crowdfund — Payment Retry & Cancellation BRD v1

After batch-charge: 4 recovery checkpoints, then Successful payout or Cancel+refund-all
← Main BRD Lifecycle State machine Payment retry & cancellation
●
Four checkpoints, two outcomes. Decline → 3-day silent retry → 7-day email URL → day-10 waitlist swap (restart 3+7) → failure-threshold check. If failure% is below threshold → Successful + 80% payout. If above → Cancelled + refund-all-backers.

The recovery flow protects the campaign goal when individual cards decline. Instead of just dropping each failed pledge, we run a structured cycle and only cancel the whole campaign if aggregate failures exceed the threshold (BR-O1 — value still pending biz). Worst-case backer cycle = 3 + 7 + 3 + 7 = 20 days. Communicate "up to 30 days from close" to creators (10-day buffer).

Four recovery checkpoints

EACH GIVES THE DECLINING PLEDGE ANOTHER CHANCE BEFORE ESCALATING TO THE NEXT

① · 3 DAYS

Silent auto-retry

System retries the charge in background. Backer not notified. Most temporary declines (network blip, insufficient funds) clear in this window.

② · 7 DAYS

Manual recovery email

Backer receives email with a secure URL to update card. URL expires after 7 days. Backer pays on-the-spot in one session.

③ · DAY 10

Waitlist replacement

If both windows expire, drop the original pledge and pull the next waitlister into the spot. Restart the 3+7 cycle on the waitlister.

④ · AFTER ALL PLEDGES

Threshold check

After every pledge has been processed, aggregate failure %. If > threshold → campaign Cancelled, all backers refunded. Else → Successful.

Worst-case per-pledge timeline

Day 0
Campaign closes (Funded). System fires batch-charge. Most pledges clear cleanly.
Day 0 → 3
① 3-day silent retry for declines. Stripe smart-retry attempts: day 1, day 2, day 3. Backer doesn't know anything is happening.
Day 3
Recovery email sent to backers still failing. Email contains 7-day expiring URL to update card.
Day 3 → 10
② 7-day manual recovery. Backer can enter a new card and retry within the window. URL expires day 10.
Day 10
③ Waitlist swap. If still failing, drop the original backer. Pull next waitlister, lock their payment + email, restart the cycle on them.
Day 10 → 20
Waitlister recovery (3+7). Second cycle. If the waitlister also fails, that pledge is counted as lost.
Day 20
④ Threshold check. After every pledge resolved (cleared or lost): if aggregate failure% > threshold → Cancelled + refund-all. Else → Successful + 80% release.
Day 30 (SLA)
Communicated SLA. Creators are told payout takes up to 30 days from campaign close (10-day buffer over the 20-day actual worst case).

Project cancellation

CANCELLATION = AUTO-TRIGGERED BY THRESHOLD CHECK · OR MANUAL BY OPS DURING ACTIVE / IN PROGRESS

▲
Auto · Failure threshold exceeded. Set by checkpoint ④. Threshold value pending biz (BR-O1).
▲
Manual · Creator default. Withdrawal, breach of artist contract, or non-delivery.
▲
Manual · Production failure. Cannot deliver the planned content; ops calls it during In Progress.
▲
Manual · Compliance / legal. Content, IP, or regulatory issue forces cancellation.

Refunds are NOT in-product. The new BRD intentionally has no admin refund UI. All refunds run through Stripe back-office as a manual batch operation. The system's only job is to flip status + fire the cancellation email + freeze the listing.
